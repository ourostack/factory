# The factory

> The factory is the public measurement store for Desk, a plugin that gives coding agents a durable desk of tracks and tasks. It measures agentic work the way Lean measures a factory floor: where each task's time went, which part added value, and which part was waste. It names no person, no machine and no content: the only calendar facts are each task's finish day (UTC), times on a task's own clock, and pull request times from GitHub. This file indexes the data behind every view, for agents.

Site: https://ourostack.github.io/factory/
Source and raw data: https://github.com/ourostack/factory (the `reports` branch holds the built reports)

## How to walk it

The site walks the four steps Lean uses to see waste, in this order. Read the data in the same order.

1. Follow a task (`#/task/<job>`): one real task end to end, and where its time went. `#/` opens on the finished task with the latest finish position (`finish_order`), named or private: the labeled task (`finish_basis: "labels"`) with the largest `finish_order` in `rollups/tasks.json`.
2. Compare tasks (`#/compare`): every task side by side on one scale, as a stack-up of working time by label and waiting by cause, in hours of all elapsed time (`?mode=all`), hours of agent working time only (`?mode=working`) or each task's shares of its own lead time on a 0 to 100% axis (`?mode=share`), with each finished task's finish day (UTC) under its bar. Its "Over time" section reads `rollups/by_week.json`: hours per finish week for the 5 largest causes plus the rest as Other (small multiples on one linear scale from zero, stated in the caption), and each finished task's flow efficiency as a point at its finish day, with each week's median over measured tasks (n of N). A finished task with no finish day is listed with its reason, never placed on a guessed date.
3. Rank causes (`#/causes`): causes of waste ranked by the time they cost, in a Pareto chart; each cause has its own page (`#/causes/<key>`, for example `#/causes/waiting:next_prompt`) with its tasks, its stretches and a prompt that starts an A3, or, when a kaizen issue already works on that cause, a link to it and a prompt to check or extend it.
4. Act (`#/act`): the problems taken on (kaizen issues, `data.json` `kaizen_issues`), each with its countermeasure, its cause where the site maps one (`kaizen_issues[].cause`), and its check, and the issues that own the status line's alarms.

Reference pages: `#/why` (why Lean, the eight wastes and a glossary), `#/about` (how the data gets here and the privacy rules), `#/store` (everything else the store measures).

## Reading the numbers

Every number is an object `{ state, value?, reasons }`. `measured` is the whole figure. `partial` is part of it, and `bound` says whether the true figure is higher (`lower`) or lower (`upper`); when the direction is not known, `data.json` says `unknown` and every file under `rollups/` and `map/`, Desk's and the store's, says `null`, with `bound_reason` giving why where Desk states it (`reasons.json` has its words). `unavailable` means not measured: its value is absent or null, and it is never zero. `reasons` are codes; `reasons.json` gives the words the page shows for each. {{DIRECTION}} A rollup also carries `n` of `N` and what it counts. Every task has a `finish_date` (`data.json` `jobs[]`, and on each row of `rollups/tasks.json` and each file under `map/`): `{ state, value, basis, bound?, reasons }`, whose `value` is the UTC day the task finished ("YYYY-MM-DD"), never a time of day. `basis` says where the day comes from, and the first source that gives one wins: `desk_transition` (Desk's record of the day the session moved the card to done or cancelled, measured), `desk_card_updated` (the day the card was last updated, so the task finished on or before it: `partial`, `bound: "upper"`), `pr_anchor` (the task's pull requests tie its clock to GitHub's `created_at` for them, and the day is that anchor plus the end of the task's lead window: the anchor is the one that places pull request times on the map: measured when a pull request the session opened sets it or several agree; `partial` with `bound: "lower"` (the task finished on or after the day) and reason `anchor_unconfirmed` when nothing confirms the pull requests it rests on; when they disagree, `partial` with reason `anchor_spread`: with `bound: "lower"` and the added reason `anchor_unconfirmed` when the anchor rests on timed pull requests the session is not known to have opened (each of them is at or before the true start), and with no direction when pull requests the session opened disagree; when the task's lead window is partial only because the card's dates are shorter than the work, the day is that of the last recorded work, `partial`, `bound: "upper"`, reason `finish_from_last_work`; any other partial window gives reason `lead_window_partial` and no direction), `labels_landed` (the UTC day the task's waste labels first landed in the store, so the task finished on or before it: `partial`, `bound: "upper"`, reason `finish_from_labels_landing`; if the task's pull requests put its finish after that day and that anchored day is not itself an "at most" day, the labels day is shown as `partial` with no direction and reason `anchor_after_labels`, because the two disagree (two "at most" days do not disagree: the earlier one, the labels day, stands as `bound: "upper"`); when GitHub could not be read for the anchor, the labels day also carries the reason, for example `github_unreadable` or `github_lookup_capped`). A task still open has no finish day (`open_job`), a task whose status could not be read has `status_unavailable`, a desk that withholds job timing has `job_offsets_withheld`, and a finished task no source gives has `no_finish_source`. Tasks are ordered by `finish_order`: by `finish_date` value, earliest first; ties, and then finished tasks with no date, by the order in which each task's first waste labels landed in the store; open tasks and tasks whose status could not be read last, by their first facts file. In `rollups/` and `map/`, a finish day whose reasons pull both ways (an "at least" anchor and an "at most" last-work day) has `bound: null` and `bound_reason: "bound_reasons_conflict"`. `finish_basis` is `labels` for a task with labels, `date` for a dated task with none yet, and `facts` for the rest. Tasks whose labels landed in the same commit share a `finish_group` and are ordered within it by lead time, so the longest of them takes the latest position. A task's `name` is the title of its earliest-opened public pull request, or null for a private task; `name_basis: "partial"` (in `data.json`) means some of its pull requests could not be read, so an earlier one may exist. The store adds `name`, `finish_order`, `finish_group`, `finish_basis` and `finish_date` to every row of `rollups/tasks.json`. `rollups/by_week.json` (`factory.site.by_week/1`) counts each finished task in the ISO week (UTC, Monday first) of its `finish_date` (`basis: "by_finish_week"`); every week from the first finished task to the last is listed, and a week with no finished task is `{ n: 0 }`, never zero hours. Each sum is a stated number, and `n_partial` counts the tasks in a week that rest on a partial figure. A finished task with no finish date is under `unplaced`.

"Waiting" means idle time only: lead time minus working time, when no agent was working on the task. It is split by what it waited on (`waited_on`): `next_prompt` (the agent had stopped for the operator's next prompt), `other_task` (a session of the task was running, but its agent was working on another task; the other task is never named), `api_retry`, `tool_failure`, `long_tool_call`, `queue_before_start`, `no_session` (no session of the task was running) and `unknown` (no agent was working on the task, and the cause was not recorded). A gap's `waited_on` is its largest cause; where Desk gives `gaps[].idle_by_waited_on_ms`, that is the gap's exact split. The evaluator's labels (value-adding, necessary, each waste) describe working time only.
