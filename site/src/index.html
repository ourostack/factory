How much operator attention does an accepted outcome cost, and where does the rest go?

This store is for anyone deciding how to get more accepted outcomes for less human attention: an operator, a team lead, or an agent improving its own system. The value it cares about is an outcome a human accepted. Everything measured here serves one question: how much human attention does an accepted outcome cost, and where does the rest go? Agent time, tokens and tool calls are inputs; they matter only because they help explain that ratio.

Designed for many desks; proven on one so far.

What an accepted outcome costs

An outcome counts as accepted when the operator accepts the delivery. The agent records that answer on the operator's word. Attention spent on work that was sent back or is still waiting stays in the cost.

    How to read this

    • Start at the top. "At a glance" says whether you can trust the page today. "What an accepted outcome costs" is the answer the factory exists to give. "What to fix next" is what to do about it.
    • A plain figure was measured. A figure marked at least 12partial was only partly measured; "at least" or "at most" says which way the true figure lies, and the reason is on hover and in text for screen readers.
    • "No data" is never zero. A figure shown as no data(with its reason) was not measured. A zero appears only when zero was measured.
    • Every total says what it rests on, for example "12 of 31 jobs". A trust note beside a headline says, in words, whether its sample is thin or partial.
    • Tasks are anonymous. The store publishes a one-way key per task, never its name. On the operator's own machine, a private local-names.json next to the page shows the real names instead.
    • Accepted means the operator's word, recorded by the agent through Desk's sign-off tool.

    So what are they doing the rest of the time?

    A long session is not automatically a well-run one. Once an agent can work for hours or days at a stretch, the next question is an industrial-engineering question: where does the time actually go — value-adding work, necessary support, or waste — and can the system around the agent be redesigned to move more of it toward value? This studies the work, not the worker. There are no leaderboards here and nothing about any one person or agent.

    What the data shows so far

    Do humans accept what agents deliver?

    Value is an outcome a human accepted. When an agent delivers, the operator accepts it or sends it back with a reason, and the agent records that answer on the operator's word. First-pass yield is the share of delivered jobs accepted with nothing sent back. Jobs whose card predates sign-off are out of scope and counted beside each figure. Nothing here says who signed or when.

    How this data gets here

    Desk is a plugin that gives coding agents (Claude Code, Copilot CLI, Codex) a durable "desk" of tracks and tasks. The factory is how that work gets measured.

    1

    A session ends

    The host publishes an anonymous facts file: tool calls, failures, retries, models, tokens, subagents, time intervals, which job it touched.

    2

    CI validates & merges

    Every field is checked against the published schema. No transcript text, prompt, file content or identity is ever accepted.

    3

    CI builds reports

    A job's timeline is rebuilt and its report published: what happened, what mattered, what was waste, what we could not see.

    4

    An evaluator labels waste

    An independent agent classifies finished stretches as value, necessary support, or one of the eight Lean wastes — citing evidence, never grading itself.

    5

    Kaizen closes the loop

    Evidence becomes an improvement issue naming the measure, the countermeasure and, once it ships, whether the data confirms it helped.

    No who, no when, just how

    No who

    No contributor, operator, account, machine, host name, desk path or branch appears in any facts file. A job is identified only by a one-way hash.

    No when

    Facts carry durations and offsets from the session start, never a date, a time of day or an epoch value.

    No content

    No transcript text, prompt, response, tool argument, file content, file path or task title ever leaves the contributor's machine.

    Public references only

    References to private repositories are dropped and only counted. Public pull requests and commits — the evidence on this page — are, like any GitHub contribution, already public.

    Contribution is opt-in, asked once per machine. The measurement rubric is public and open to review: RFC section 4 and the evaluator's rubric.
